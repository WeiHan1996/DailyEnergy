## 1. 当前目标

把已接受的产品状态机转换为可执行、可验证但仍不绑定技术实现的业务规则，解决点亮、跨日、中断恢复和通知在正常、重复、离线、多端、删除与 Safety 场景中的具体行为。

本任务回答：

- 什么条件下用户可以点亮，重复点亮和点亮失败如何处理；
- 当前页到达主要行动、服务端点亮守卫和关系相遇日如何协作；
- 产品日期变化时，正在阅读、正在生成、未提交草稿和旧日写入如何处理；
- 用户中途退出、客户端超时、网络中断和多端恢复时回到哪里；
- 任务、帮助度和晚间反馈在同日及跨日的可修改边界；
- 删除当前日后是否允许明确重新提交，以及如何避免自动重建；
- 关系节点被删除源日影响后，未来再次跨过阈值时怎样展示；
- 什么时候可以请求通知权限、允许哪些提醒、如何取消和去重；
- 通知深链过期、Safety、Deleting、账户限制和离线时如何安全降落；
- 如何欢迎中断后回来的用户而不制造断签、损失或关系压力。

本文不定义精确时区算法、数据库字段、API、Schema、通知平台代码或前后端实现。

## 4. 已接受且不得重开的决策

- 每日结果与生成执行是独立状态域；
- 每日结果按用户、产品日期和结果版本唯一且不可重新抽取；
- 签到可以在后续规则窗口内更正，但不重生成；
- 到达主要行动只是客户端派生状态，不持久化；
- 点亮表示完成核心阅读，不表示任务完成、运势应验或完美连续；
- 点亮服务端守卫依赖有效结果与覆盖状态，不保存滚动像素；
- 关系天数按去重的有效点亮日计数，中断不清零；
- 删除点亮源日后关系、节点、趋势和总结必须重算或失效；
- 小任务、内容帮助度、晚间反馈和点亮彼此独立；
- 同产品日期的晚间反馈可修改，历史默认只读；
- 模板或备用模型降级是结果元数据，不是用户状态；
- Safety、Deleting、账户限制和阻断维护优先于缓存、深链和普通旅程；
- Offline 只读，MVP 不做离线写队列；
- 客户端超时不等于服务端失败，恢复前先读正式状态；
- 删除中的账户只开放删除状态、必要说明和支持；
- 中断不使用断签、损失、责备或数字朋友受伤的表达；
- 通知是可选能力，权限拒绝不改变核心每日状态。

## 5. 必须固化的不变量

- 同一产品日期点亮最多产生一个有效事实和一个相遇日；
- 点亮不依赖任务、帮助度或晚间反馈；
- 重复命令、超时重试和多端操作不能重复计数；
- 旧页面写入不能被错误归到新产品日期；
- 跨日不会自动复制签到、生成意图、草稿或结果；
- 当前页面不会在零点突然替换正在阅读的内容；
- 未提交草稿不是服务端事实，也不跨设备自动合并；
- 同日修改使用最新修订或明确冲突处理；
- 历史结果冻结，规则升级和偏好修改不重写；
- 当前日删除后不得自动重建任何事实；
- 删除、Safety、账户限制和用户关闭提醒后，相关待发送通知必须取消或失效；
- 同一提醒意图不得因重试或多设备安排重复发送；
- 通知不能制造坏运势紧迫感、断签损失或关系压力；
- 过期深链不能补填、重抽或绕过高优先级覆盖；
- 中断和缺失日期如实保留，不补造趋势或关系记录。

## 7. 规则建议边界

文档应优先给出可解释的产品规则，而不是实现参数。可以定义：

- “原产品日期”“当前产品日期”“写入窗口开放”等业务条件；
- 最大发送频率、同类提醒去重和用户静默时段；
- 深链资格、取消条件和过期行为；
- 中断恢复的权威读取顺序；
- 同日可改、历史只读和明确重新提交的产品行为。

文档不能提前决定：

- IANA 时区、零点宽限分钟数或稳定种子算法；
- 微信订阅消息模板 ID、平台调用方式或审核结果；
- 数据库锁、队列、Cron、幂等键字符串或缓存 TTL；
- API 路径、HTTP 状态、错误码或 TypeScript 类型。

## 8. 不在当前任务范围

- 精确产品时区、零点宽限和日期算法；
- 稳定种子、评分和结果版本算法；
- 今日内容、反馈或总结的 JSON/Zod Schema；
- 数据库表、索引、事务和迁移；
- API 契约与错误码；
- 微信订阅消息能力的最终技术验证；
- Prompt、AI Gateway、模型重试与熔断参数；
- 高风险分类、地区资源和 Safety 恢复条件；
- 数据保存期限、依法保留和删除完成时限；
- 前端、后端、管理后台、通知服务或测试代码；
- 实际发送通知、联系用户或招募测试；
- 新增连续签到、补签、积分、聊天或付费功能。

## 9. 验收标准

- 每条规则能追溯到已接受状态和用户价值；
- 点亮正常、重复、离线、失败、删除和多端行为无歧义；
- 跨日覆盖阅读、生成、提交、草稿、旧日写入和深链；
- 中断恢复矩阵覆盖全部核心流程；
- 通知默认克制、用户控制、可取消、可去重且无压力；
- Safety、Deleting、账户和维护覆盖规则完整；
- 同日修改、历史只读和当前日删除后行为明确；
- 关系节点重放规则不会制造重复奖励或情绪压力；
- 至少包含规则表、决策表、时间线和 8 个验收序列；
- 所有延期决定有明确负责的后续任务；
- 文档索引和任务状态同步；
- 通过独立 Draft PR 提交；
