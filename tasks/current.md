## 1. 当前目标

把已经接受的用户旅程和 MVP 功能转换成完整页面结构，使产品、设计、前端、后端和后续 AI Agent 对“有哪些页面、从哪里进入、怎样跳转、每种状态落在哪里”形成同一理解。

本任务不设计最终视觉，也不编写业务代码。

## 3. 必须覆盖的用户路径

### 新用户首次路径

> 渠道触达 → 小程序承接 → 身份建立 → 称呼与表达偏好 → 今日状态签到 → 内容生成 → 今日内容 → 行动建议 → 点亮

### 当日再次进入

> 打开小程序 → 读取已生成结果 → 回看行动 → 更新任务状态或进入晚间反馈

不能重新抽取当天核心结果。

### 晚间路径

> 晚间入口 → 真实感受 → 建议帮助度 → 任务结果 → 可选一句话 → 简短收尾

### 连续 7 天

> 每日核心循环 → 第 3 天表达校准 → 第 4 天可选重要事项 → 第 7 天趋势与总结

### 中断回来

> 欢迎回来 → 保留历史 → 从今天继续

不得要求补签或使用责备文案。

### 用户权利

> 设置 → 查看资料与记忆 → 修改或删除 → 导出主要数据 → 注销或结束关系数据

### 异常路径

- 登录失败；
- 权限拒绝；
- 网络中断；
- 当日结果正在生成；
- AI 超时；
- Schema 校验失败；
- 本地模板降级；
- 重复提交；
- 跨日期；
- 数据不足；
- 高风险安全分支；
- 服务维护。

## 5. 关键约束

- 第一次体验约一分钟；
- 首次不强制生日、作息和重要事项；
- 只有一位核心数字朋友；
- 三种表达偏好不是三个角色；
- 今日能量与真实状态视觉和数据上分开；
- 当天结果稳定；
- 点亮不要求完成任务；
- 晚间反馈可选；
- 第 4 天重要事项可跳过；
- 中断不惩罚；
- 分享默认隐藏敏感内容；
- 不在首屏索取通知权限；
- 高风险内容退出普通旅程；
- 页面结构不能暗中加入无限聊天、专业算命、社区和商城。

## 7. 验收标准

- 所有 P0 MVP 能力能映射到页面或明确的后台系统状态；
- 每个页面有唯一 ID；
- 没有孤立页面和无入口功能；
- 新用户、每日返回、晚间、七天、中断和删除流程完整；
- 正常、加载、空、错误、离线、降级和安全状态有归属；
- 能清楚区分小程序、服务端和管理端；
- 信息架构不依赖无限聊天；
- 页面数量保持 MVP 克制；
- 与 vision、persona、journey、mvp、personality 和 ADR-0001 一致；
- 两份文档互相链接；
- docs/INDEX.md 状态同步；
- 通过独立草稿 PR 提交；
- 用户确认后将文档状态更新为 Accepted。

## 8. 需要特别评审的决策

本任务需要提出建议并在 PR 中显著列出：

1. 首页是“今日内容页”还是独立导航首页；
2. 首次认识需要几屏；
3. 五维状态一次展示还是渐进展开；
4. 晚间反馈从哪里进入；
5. 历史回看是否只提供七天，还是保留日历入口；
6. 重要事项放在首页、设置还是独立页面；
7. 设置和隐私是一个页面还是分层页面；
8. 是否需要底部 TabBar；
9. 分享卡片在今日内容和七天总结中的位置；
10. 模型降级时是否向用户显示状态说明。

本任务只给出推荐方案，不擅自把争议项标记为最终决定。用户在 PR 中确认后再进入 Accepted。
