## 1. 服务承诺与边界

用户支持帮助用户理解产品、报告故障、反馈内容、处理账户问题并进入正式用户权利流程。它不是无限聊天入口，也不是医疗、心理、法律、投资或危机响应服务。

支持流程必须做到：

- 先用版本化 FAQ 解决可自助问题；
- 只接收完成当前请求所需的最小数据；
- 用户自由文本先通过 Schema 与 T0 Safety Gate；
- high-risk 输入退出普通支持，不建立含原文的工单，不承诺人工危机响应；
- 支持人员只看被分配案例的白名单视图，不能任意浏览用户全文或产品历史；
- 数据权利任务以 `DataTask` 为权威，支持 case 只保留 opaque ref 与可披露状态摘要；
- 回答、纠正、升级、关闭、保存与删除都可追踪。

本文为 Draft 时，现有 `/support/feedback` 仍只能完成 T0 校验后丢弃，不能持久化或人工转交。只有本文被接受且 S-29/后续工程完成目标合同、权限、删除、导出与测试后，该 Gate 才解除。

## 2. 入口与请求类型

### 2.1 用户入口

1. `GET /support/faq`：读取版本化 FAQ；
2. 设置页“帮助、反馈与关于”：选择分类并可选填写不超过 500 字说明；
3. 当前内容页“内容有问题”：明确选择是否附带当前可见输出；
4. 数据与隐私页：直接创建或查看 `DataTask`，支持只提供导航和状态解释；
5. 账户删除或恢复流程中的必要支持入口：只处理当前删除/恢复所需信息。

不通过普通邮件、即时通讯群、公开评论或个人账号接收正式支持材料。实际外部客服受托方未评审前，不配置自动转发。

### 2.2 与现有 OpenAPI 对齐的分类

| API `category` | 运营含义 | 默认去向 |
|---|---|---|
| `BUG` | 功能故障、弱网、加载、状态不同步、可复现错误 | 技术支持队列；必要时交 S-23 |
| `CONTENT` | 生成内容质量、事实绑定、人格、重复、分享或内容申诉 | 内容审核流程 |
| `PRIVACY` | 隐私咨询、数据查看/导出/更正/删除协助 | FAQ 或 `DataTask`；普通 case 不替代正式任务 |
| `ACCOUNT` | 登录、会话、账户状态、删除/恢复受阻 | 账户支持；高风险操作必须走既有重认证 |
| `OTHER` | 不能由用户可靠归类的产品问题 | 初次分流后必须改为明确队列，不作为长期最终分类 |

一般产品咨询优先由 FAQ 处理；FAQ 未解决时可用 `OTHER` 提交。`DATA_RIGHTS` 不新增为 API 分类，正式权利请求继续使用现有 Data Rights 端点。

## 3. 受理前 Safety 与最小化 Gate

可选 `description` 的固定处理顺序：

1. 客户端展示“请勿填写身份证、银行卡、病历、密码或紧急求助内容”的短提示；
2. 服务端验证已接受 `SupportFeedbackRequest`：分类为封闭枚举，说明为可选且最多 500 字；
3. 只在 T0 内存中执行 Safety 分类，不写请求 body、日志、trace、队列或分析；
4. `HIGH_RISK`：停止普通提交，展示固定 Safety 响应；不保存原文、不创建普通 case、不转人工；
5. `INDETERMINATE`：fail closed，不保存；提示用户移除/缩短说明或稍后重试；
6. `CLEAR` / 非高风险：继续最小化，剔除不允许字段，按用户明确选择附带最小 `client_context` 或当前可见输出；
7. 创建目标 `SupportCase`，返回可查询的 case ref；在该能力实现前继续丢弃，不返回虚假的工单状态。

固定 Safety 响应展示后，用户可重新发起一个不含原说明的普通产品问题。这个新 case 只包含新分类和新内容，不能标记、暗示或复制前一次 high-risk 原文。

## 4. 目标 SupportCase 合同

S-22 冻结的是后续实现必须满足的最小运营合同，不直接修改 Prisma 或 OpenAPI。

### 4.1 最小字段

| 字段组 | 最小内容 | 约束 |
|---|---|---|
| 身份与所有权 | opaque `case_ref`、账户 owner 关联、创建时间 | 客户端不接收内部 UUID；普通后台不能按用户任意搜索 |
| 幂等 | `command_ref` / idempotency key | 同一命令只创建一个 case |
| 分类 | 现有 `category`、队列、优先级、封闭原因码 | `OTHER` 分流后改为明确队列 |
| 状态 | 当前状态、revision、最后状态时间 | 使用 CAS；不静默覆盖并发更新 |
| 用户材料 | 可选加密 `description`、用户明确选择的最小附件/内容快照 | 不含 Safety 原文；正文最多 500 字；不自动附带产品历史 |
| 技术上下文 | 已接受 `ClientContext` 白名单、request ID、稳定错误码、相关 opaque ref | 禁止完整 headers、cookie、token、IP、设备指纹、日志 body |
| 处理 | 分配角色/队列、回复摘要、下一步、关闭原因 | 只允许案例级访问 |
| 关联 | 可选内容 ref、`DataTask` ref、事件 ref | 只存 opaque ref，不复制受限详情 |
| 保存 | `retention_policy_version`、anchor、`expires_at` | 每类正文与元数据都有上限 |

支持正文和回复必须应用字段级加密；普通查询列表只返回分类、状态、时间、优先级和无敏感摘要。任何全文查看都必须是分配案例内的明确操作。

### 4.2 明确禁止的字段

- 密码、验证码、session、access/refresh token、WeChat code；
- 身份证、银行卡、病历、诊断书或未定义的身份材料；
- Safety high-risk 原文、模型 Prompt/原始响应、完整签到/note/事项/记忆；
- 完整 IP、设备指纹、通讯录、地理位置或社交关系；
- 为方便运营而复制的数据库行、对象 body、DataTask 或 RestrictedAuditEvent 全文；
- 未经评审的外部客服账号、邮件地址、IM 标识或营销标签。

## 5. 状态、优先级与服务时限

### 5.1 Case 状态

```text
RECEIVED → TRIAGED → IN_PROGRESS → RESOLVED → CLOSED
                    ↘ WAITING_USER ↗
```

- `RECEIVED`：已通过 Gate 并成功持久化；
- `TRIAGED`：分类、优先级和队列已确认；
- `IN_PROGRESS`：已分配处理；
- `WAITING_USER`：只等待解决当前问题所需的最小补充；
- `RESOLVED`：已有结论、修复、解释或正式任务链接；
- `CLOSED`：用户确认，或 7 个自然日无新回复后自动关闭；
- `CANCELLED`：用户在开始处理前撤回；
- `MERGED_DUPLICATE`：语义重复，链接到 canonical case；不复制正文。

状态只能按允许转换推进，所有变化使用 revision/CAS 并保留案例事件。`WAITING_USER` 不能成为无限保存理由：30 个自然日无回复必须关闭。

### 5.2 支持优先级

| 优先级 | 示例 | 确认收到 | 完成初次分流 | 目标结论 |
|---|---|---:|---:|---:|
| `SUP-P1` | 账户无法进入、删除/导出任务受阻、广泛数据暴露迹象、资源明显错误 | 4 个工作小时 | 1 个工作日 | 2 个工作日内解决或给出明确升级与更新时间 |
| `SUP-P2` | 核心流程故障、内容硬边界疑似漏判、持续重复错误 | 1 个工作日 | 2 个工作日 | 5 个工作日 |
| `SUP-P3` | 一般内容反馈、非阻断故障、账户咨询 | 1 个工作日 | 2 个工作日 | 5 个工作日 |
| `SUP-P4` | 产品建议、FAQ 建议、非时效问题 | 2 个工作日 | 3 个工作日 | 10 个工作日或合并到规划反馈 |

服务窗口为中国法定工作日 09:00～18:00，时区 `Asia/Shanghai`。时限是 Alpha 运营目标，不是 24×7 承诺。high-risk Safety 输入不进入本表，也不能以 `SUP-P1` 冒充危机值守。

DataTask 的身份验证、范围、状态和完成时限继续服从 Accepted 数据权利契约；支持 SLA 不延长也不替代法定或上游更严格期限。

## 6. 标准处理流程

### 6.1 FAQ 与受理

1. 优先展示与当前页面、错误码和版本匹配的 FAQ；
2. 用户确认未解决后选择分类；
3. 可选说明通过第 3 节 Gate；
4. 系统返回 case ref、当前状态、预期首次回复时间和撤回入口；
5. 支持人员只从分配队列打开案例白名单 View。

### 6.2 分流与处理

1. 核对分类、优先级、重复 case 和允许的技术上下文；
2. 不要求用户重复系统已经持有且允许披露的结构化事实，也不索取无关材料；
3. `BUG` 先用稳定错误码、request ID 和合成复现；不得从生产日志捞取正文；
4. `CONTENT` 进入 `content-moderation.md`，历史稳定内容不由客服后台直接修改；
5. `PRIVACY` 需要实际查看、导出或删除时，引导创建 `DataTask`，支持 case 只保留 task ref 与可披露摘要；
6. `ACCOUNT` 的重认证、删除和恢复必须走既有端点；客服不能手工跳过；
7. 无法按普通流程解决时按第 7 节升级。

### 6.3 回复、纠正与关闭

- 回复说明“我们确认了什么、做了什么、用户下一步是什么、何时再更新”；
- 不暴露内部安全规则、其他用户信息、供应商 raw response、受限审计或不可披露证据；
- 发现答复错误时追加 `CORRECTION`，标记旧答复已取代，不静默改写；
- `RESOLVED` 后用户可继续回复 7 个自然日；无回复自动 `CLOSED`；
- 关闭后 30 个自然日内可申请一次复核；由未参与首次结论的 `SUPPORT_LEAD` 处理；
- 重复请求链接到原 case，不能复制正文或通过重复提交无限延长保存期。

## 7. 升级与失败处理

| 触发 | 升级对象 | 支持队列保留内容 |
|---|---|---|
| 多用户同类故障、数据丢失、认证异常 | S-23 事件响应 / 工程 on-call（待定义） | case ref、错误码、版本、影响摘要；无正文复制 |
| 疑似隐私暴露、越权或删除失败 | Privacy/Security + S-23 | opaque ref、时间、范围和可披露摘要 |
| 普通生成内容硬边界漏判 | 内容审核负责人；系统性问题交 S-23 | 用户明确提交的最小输出与版本 |
| Safety 资源错误或系统性漏判 | Safety policy owner + S-23 | 无原文事件 ref、版本、地区和原因码 |
| DataTask 卡住或摘要冲突 | `PRIVACY_OPERATOR` | task ref、公开状态与阻塞码 |
| 支持工具不可用 | S-23；前台展示稍后重试 | T0 请求不落本地文件、邮件或个人 IM |

升级失败时，case 保持原状态并显示“已升级、等待负责人”，设置下一次更新时间；不能把材料复制到非受控渠道兜底。达到事件阈值后的响应、通知和复盘由 S-23 定义。

## 8. 用户权利与受限摘要

### 8.1 普通支持可见

- 自己被分配 case 的分类、状态、最小正文、用户明确附件和回复；
- 相关内容/请求的 opaque ref、版本、稳定错误码；
- DataTask 的用户可见状态、创建时间、范围名称、下一步和完成/失败摘要；
- Safety 的公开产品说明与资源版本，不含个案原文或受限事件细节。

### 8.2 受限域摘要

当用户询问 Safety、删除或受限审计时，普通支持不得直接打开受限表。它向相应受限角色发起摘要请求，包含 case ref、目的码、所需字段和期限。受限角色只返回：

- 是否存在与用户请求范围相关的记录；
- 记录类别、保存依据、到期时间或删除状态；
- 可披露的处理结果、拒绝/限制理由和申诉路径；
- 不含 raw text、稳定主体标识、内部策略细节或第三方数据的摘要。

受限记录不能因为“受限”而自动排除在用户查看、导出或删除请求之外。`PRIVACY_OPERATOR` 必须按 Privacy Data Map 第 12.1 节逐项判断可披露、可删除、需限制或需 legal hold 的范围，并把可披露结论返回给用户。

### 8.3 更正、导出与删除

- **更正**：用户可更正当前 case 中自己提供的非 Safety 信息；系统以追加更正保存审计，不改写历史答复。产品事实仍在各自权威模型中更正。
- **导出**：目标实现必须把仍在保存期的 case 元数据、用户材料、回复与关联状态纳入用户导出；受限域只给可披露摘要。
- **撤回**：处理前可 `CANCELLED`；已处理则停止后续普通使用并按删除队列清理。
- **独立删除**：目标实现必须允许用户删除一个 support case，而不要求删除整个账户；当前 DataTask/OpenAPI 没有 `SUPPORT_CASE` scope，因此该能力是 S-29/C-014 production blocker。
- **账户删除**：case、正文、附件、索引和缓存属于账户删除范围，在线副本 72 小时内删除；只保留 ADR-0005 允许的最小删除证据。
- **备份**：删除标记阻止恢复后重新服务，备份最长 35 天自然老化；恢复演练必须重放 deletion guard。

在导出、独立删除、受限摘要和 deletion guard 集成完成前，SupportCase 不得在生产持久化。

## 9. 角色、最小权限与 break-glass

| 角色 | 允许 | 禁止 |
|---|---|---|
| `SUPPORT_AGENT` | 查看被分配 case 的白名单 View；用批准模板回复；请求升级 | 任意用户搜索；查看 Safety/删除/审计原文；跳过重认证 |
| `SUPPORT_LEAD` | 分配、合并重复、批准纠正、处理再次复核 | 批准自己的受限访问；修改产品事实或 Safety 状态 |
| `CONTENT_REVIEWER` | 查看用户明确提交的最小内容反馈 | 查看其他支持材料、身份、签到、记忆或 Safety 原文 |
| `PRIVACY_OPERATOR` | 处理 DataTask、生成可披露受限摘要、执行权利决定 | 把受限全文复制给支持；把 case 当作权利任务权威 |
| `SAFETY_POLICY_REVIEWER` | 查看无原文 Safety 摘要、版本和合成复现 | 承担个案危机值守；要求普通支持收集 high-risk 原文 |
| `SECURITY_APPROVER` | 独立审批必要受限读取、审查访问异常 | 作为请求人审批自己的提权 |
| `SUPPORT_SERVICE` | 按目的码读取/写入 case、执行到期与删除任务 | 读取业务域任意全文或复用数据做 analytics/营销 |

### 9.1 break-glass

只有已登记事件或明确用户请求在普通摘要无法解决时才能申请：

1. 请求人提交 ticket ref、目的码、精确对象范围、字段列表和预计时长；
2. 与请求人不同的 `SECURITY_APPROVER` 或 `PRIVACY_OPERATOR` 审批；
3. 访问默认只读、字段级、案例级，最长 60 分钟；
4. 系统自动撤销，不允许续租；需要继续时重新申请；
5. 每次请求、批准、读取、拒绝、导出尝试和撤销写入 `RestrictedAuditEvent`；
6. 禁止复制到剪贴板、下载、日志、普通 case 或个人工具；必要导出必须走单独受控流程；
7. break-glass 不能绕过 deletion guard、legal hold 决定或恢复 T0 已丢弃原文。

### 9.2 RestrictedAuditEvent 最大期限

S-22 冻结 `RestrictedAuditEvent.expiresAt` 的普通最大期限为：

- 从 `finishedAt` 起 **6 个自然月**；没有 `finishedAt` 时从 `requestedAt` 起算；
- `expiresAt` 必须在事件创建时写入，不能为 null，不能被普通运营延长；
- 到期硬删除，不转存到 SupportCase、分析仓库或普通日志；
- 依法保留只能创建独立 `LegalHold` 关联，明确依据、范围和每 90 天复核；不得直接把 `expiresAt` 改为永久；
- S-29 必须实现数据库约束/服务校验、到期 worker、权限与测试；完成前受限访问能力保持关闭。

该期限与 ADR-0005 的网络安全日志、删除凭证 6 个月上限对齐，同时短于无限期保留。用户接受本 Draft 后，此项成为 S-29 的权威运营输入；若要延长必须修改 ADR-0005 或创建新 ADR。

## 10. 保存、删除与受托方

| 数据 | 权威位置 | 访问者 | 普通最长保存 | 删除 |
|---|---|---|---|---|
| FAQ 内容与版本 | 配置/内容域 | 用户、支持、发布角色 | 当前版本及回滚所需历史；由 S-29/S-32 冻结工程期限 | 版本淘汰清理 |
| SupportCase 最小元数据与状态事件 | 支持域目标合同 | 分配的支持角色、用户自己的 View | `CLOSED` 后 90 天 | 到期硬删除；账户删除 72 小时内在线删除 |
| 用户 description、回复与明确附件 | 支持域字段级加密 | 当前分配角色、用户自己的 View | `CLOSED` 后 30 天；无论状态如何从创建起不超过 180 天 | 到期/用户删除硬删除；不转训练或分析 |
| 内容问题最小输出快照 | 支持域，不进入评测语料库 | 分配支持与内容审核角色 | 同正文：关闭后 30 天，绝对上限 180 天 | 到期/用户删除硬删除 |
| DataTask 关联 | Data Rights 域为权威；case 仅 opaque ref | 用户、support 摘要、privacy operator | case ref 随 case；DataTask 按自身 Accepted 期限 | 各自删除，不复制任务详情 |
| Safety/删除/审计摘要 | 受限域为权威；case 只保存可披露结论 | 用户、分配支持、受限角色 | case 摘要关闭后 90 天；受限源按自身期限 | 各自期限删除 |
| RestrictedAuditEvent | restricted evidence schema | 独立 privacy/security 审计角色 | 6 个自然月 | `expiresAt` 到期硬删除；LegalHold 例外 |

其他规则：

- case 进入 `WAITING_USER` 30 天必须关闭；不能用“未关闭”无限保存正文；
- 到达 180 天绝对上限仍未解决时，删除旧正文并要求用户重新明确提供当前必要信息；
- 删除队列优先于普通处理、抽检、导出生成和通知；
- 搜索索引、缓存、队列和对象附件必须随权威删除失效；
- 备份最长 35 天；恢复后先重放 deletion guard；
- 未成年人生产策略、真实客服供应商、数据处理协议、处理地区和跨境状态没有 Accepted 结论前，SupportCase 持久化与外部转发保持关闭；
- 不把 SupportCase 用于 analytics、营销、模型训练、Prompt 优化或用户画像。

## 11. 重复、滥用与异常

- 同一 idempotency key 返回同一结果，不创建重复 case；
- 语义重复由支持负责人链接到 canonical case，正文不复制，最早 case 的保存锚点不被刷新；
- 速率限制只使用最小技术信号，不采集新设备指纹；被限流时保留 FAQ 和必要数据权利入口；
- 恶意内容仍先过 Safety 与 Schema；普通支持不需要接触被拒原文；
- 用户处于 `DELETING` 时，只允许完成删除、导出状态解释和必要身份恢复；不创建一般内容/产品 case；
- 支持工具失败时不把用户材料下载到本地、个人邮箱、表格或 IM；提示稍后重试并交 S-23；
- 任何人发现权限异常、批量读取、导出失败、删除复活或资源错误，立即停止相关能力并交 S-23。
