## 1. 目的

本文规定 DailyEnergy 怎样提出、运行、观察、停止和复盘实验，避免小样本、反复切片和不完整数据制造虚假结论，也避免“实验”绕过已经接受的产品、安全和隐私边界。

核心验收句是：

> 每个实验必须在曝光前冻结假设、实验单位、唯一主指标、成熟窗口、最小有意义变化、样本与停止规则；任何 Safety、隐私、删除或数据质量 Gate 失败都优先停止，不能用留存提升抵消。

本文不建立实验平台，不授权个人级随机 assignment，不创建用户级事件历史，也不把实验结果自动变成上线决定。

## 2. 不可实验的硬边界

以下内容永远不作为变体：

1. Safety 输入 Gate、固定高风险响应、资源入口、恢复路径或资源号码；
2. 必要同意、隐私说明真实性、数据查看/导出/删除、账户注销和保存期限；
3. 诊断、治疗、投资、法律等专业边界；
4. 稳定种子、同日核心结果一致性、真实签到与娱乐分离、历史不重抽；
5. 模型失败后的完整本地模板降级；
6. 默认关闭通知、用户主动授权、频率上限、静默和退订能力；
7. 恐惧、低分威胁、坏运势、断签清零、关系受伤、羞辱或排他性依赖；
8. 为提高指标隐藏缺失、Unknown、模板降级、样本量、删除或失败；
9. 采集自由文本、Safety 原文、事项、签到值、设备、IP、session 或跨日用户轨迹；
10. 以儿童、疑似高风险用户、删除中的账户或未通过必要同意的人群作为实验对象。

硬边界冲突不是实验结果，而是发布缺陷或事件，应按[故障和安全事件响应](../operations/incident-response.md)处理。

## 4. 支持的证据方法

### 4.1 EX-METHOD-01 合成与离线评测

适合 Prompt、表达、模板和安全回归。必须使用合成主体和已接受的评测语料；真实用户输入不能复制到实验集。

- 不产生用户曝光；
- 先通过 Schema、人格、安全和降级 Gate；
- 结果只证明候选可进入小范围人工或在线验证；
- 不能替代真实可用性和留存证据。

### 4.2 EX-METHOD-02 受控可用性测试

适合页面顺序、理解成本、文案清晰度和一分钟流程。

- 原型阶段 5～8 人，内部 Alpha 10～20 人；
- 任务、观察和访谈问题在开始前固定；
- 报告参与人数、完成情况和具体阻塞，不用百分比掩盖人数；
- 自由文本研究材料不进入通用 analytics；独立研究合同未接受时仅按当前研究计划人工受控处理。

### 4.3 EX-METHOD-03 发布批次比较

适合修复前后、版本迁移或单向发布验证。

- 不是随机试验，结论必须标为 OBSERVATIONAL；
- 固定版本生效时间、环境、资格、观测窗口和已知同期变化；
- 不能把渠道结构、节假日、故障或模型路由变化解释成变体效果；
- 若无法排除同期变化，只能决定继续观察或回滚，不能宣称因果提升。

### 4.4 EX-METHOD-04 产品日期 switchback

v1 唯一允许的在线对照方法：服务端按预注册产品日期日历让所有合格用户看到同一低风险版本。

- 变体日历在首个曝光前冻结；
- 日期选择使用与结果无关的预生成随机序列或平衡序列；
- 分析单位是产品日期/发布单元，不是个人；
- 一个用户可能跨日接触不同版本，因此不用于需要无 carryover 的人格、记忆、关系或长期教育变体；
- 不在客户端持久化实验标识，不通过深链、渠道参数、cookie 或设备 ref恢复分组；
- 暂停、回滚或故障日期保留为异常单元，不静默改写日历；
- 只有单元数、样本和成熟窗口足够时才做预注册比较，否则为 INCONCLUSIVE。

### 4.5 当前不支持的方法

- 个人、账户、设备、session 或关系周期级随机分配；
- 多臂老虎机、自动胜者、个性化探索、bandit；
- 多因素或全因子实验；
- 渠道 × 实验 × 用户留存的高维联接；
- 根据情绪、精力、睡眠、事项、帮助度、Safety、模型或成本动态分配；
- 暗中延长、缩短窗口或反复查看后选择最好结果。

## 5. 实验生命周期

```text
IDEA → DRAFT → REGISTERED → QA_READY → RUNNING
                     ↘ REJECTED
RUNNING → COMPLETED → DECIDED → ARCHIVED
RUNNING → PAUSED → RESUMED
RUNNING/PAUSED → STOPPED_GUARDRAIL
```

- IDEA：只有问题，不能产生用户曝光；
- DRAFT：补齐合同，仍可修改；
- REGISTERED：冻结版本与哈希；修改关键字段必须新建 revision；
- QA_READY：合成、契约、回滚和观测检查通过；
- RUNNING：仅按冻结日历/版本运行；
- PAUSED：未知结果、故障或数据质量问题，暂停不等于失败；
- COMPLETED：最终成熟窗口关闭；
- DECIDED：记录五种决定之一和依据；
- ARCHIVED：计划、聚合结论和行动关闭；
- REJECTED：与硬边界、样本或能力不符；
- STOPPED_GUARDRAIL：任何硬 Gate 或预注册护栏触发。

禁止从 RUNNING 直接修改主指标、样本、分母、变体或最小有意义变化。需要修改时关闭当前 revision 并重新注册。

## 7. 假设、变体与资格

### 7.1 假设模板

> 对【明确场景】采用【一个具体变化】，相较【当前基线】，预计使【唯一主指标】至少变化【最小有意义变化】，同时【硬 Gate 和护栏】不恶化，因为【可证伪机制】。

“更有感觉”“更像朋友”“应该提高留存”不是可执行假设，除非先有独立、已接受的研究输入与指标合同。

### 7.2 变体规则

- `CONTROL` 必须是当前可发布基线，不得故意劣化；
- `TREATMENT_*` 每次只改变一个可描述因素；
- 变体代码为低基数封闭枚举，不嵌入日期、渠道、用户或内部 ref；
- 核心事实、Safety、降级和删除行为在所有变体完全一致；
- 同日结果已发布后不因变体切换而重算；
- 变体下线后历史按当时版本真实展示。

### 7.3 允许候选

通过对应产品/安全评审后，可候选：

- onboarding 示例的表达与信息顺序；
- 今日页非核心模块的标题、折叠和说明；
- 主要行动的呈现方式，但不改变真实行动候选；
- 点亮后的克制视觉反馈；
- 首次获得价值后通知邀请的说明文案；
- 隐私安全分享卡片的非敏感主题；
- 本地模板或 Prompt 的表达质量，先走合成评测。

### 7.4 资格规则

- 资格只使用当前请求中可判定的非敏感产品事实；
- account ACTIVE、必要同意有效、非 DELETING、非 Safety 覆盖、环境 PROD；
- 不用渠道、签到值、事项、帮助度、关系阶段、模型失败或支持记录决定资格；
- 资格不可读时 fail closed：不曝光实验变化，回稳定基线；
- 资格改变不追溯修改既有事实或已发布结果。

## 8. 指标与分析计划

### 8.1 一个主指标

每个实验恰好引用一个 S-25 指标及版本。优先级：

1. 流程实验：M02～M05；
2. 回访实验：M07，必要时 M08/M09 仅作成熟次要指标；
3. 互动实验：M13、M15、M17；
4. 运行实验：M20～M23，但不能牺牲产品与 Safety。

M01、M18 等 best-effort 事件频率不能作为需要唯一用户因果结论的主指标。Q01/Q02 在研究合同接受前不可用。

### 8.2 护栏

所有实验固定包含 G01～G04；另外最多三个：

- 相邻漏斗步骤，防止局部优化转移损失；
- M20/M21/M22/M23 中与变体有关的运行质量；
- 退订、错误或降级的已接受匿名聚合；
- 一分钟流程耗时若已有可靠、最小化且 Accepted 来源。

Safety 只作为独立硬 Gate，不展示或联接风险类别、原文或个人路径。

### 8.3 最小有意义变化

`minimum_meaningful_effect` 在开始前写明绝对百分点、相对变化或时间/成本单位，并说明为何值得增加复杂度。它不是从结果反推的阈值。

### 8.4 成熟与缺失

- 指标沿用 S-25 的 D0、Dx、finalized product date、Unknown、删除和模板降级语义；
- D1/D3/D7 只有窗口成熟后进入最终判断；
- 暂停、故障、Unknown 和删除不能被当作 CONTROL 失败或 TREATMENT 成功；
- 不完整来源使实验状态 PAUSED/BLOCKED，不使用日志或客户端缓存补造。

## 9. 样本、检查点与统计读法

### 9.1 Alpha

Alpha 默认不做效果显著性判断。报告：

- 邀请、实际参与和完成的绝对人数；
- 阻塞任务与严重缺陷；
- 数据来源是否与业务事实一致；
- 可逆变更是否值得带入 Beta。

### 9.2 种子 Beta

- 总规模 50～100 人时优先完整 14 天基线，而不是同时拆多个实验；
- 每个变体/报告单元仍需 `n≥10` 才显示精确值；
- 每个比例显示 x/n 与 Wilson 95% 区间；
- 预注册最终样本或单元数未达到时只能 INCONCLUSIVE；
- 若希望声称因果效果，必须在计划中给出功效假设、基线、最小有意义变化和所需样本；所需样本超过种子 Beta 时不得降低门槛，应延期到后续阶段。

### 9.3 查看与停止

- 数据质量和硬 Gate 可持续查看并立即暂停；
- 效果判断只在预注册的成熟检查点进行；
- 不因中途点估计好看提前 ADOPT；
- 不因主指标暂时不好改成另一个指标；
- 若设置多次正式效果检查，必须预注册校正方法；v1 默认只做一次最终效果检查；
- 无论效果如何，任一 G01～G04 失败立即 STOPPED_GUARDRAIL。

### 9.4 结论语言

- ADOPT：达到预注册决策门槛且所有 Gate/护栏通过；
- REJECT：有足够成熟证据表明未达到最小有意义变化，或复杂度不值得；
- ITERATE：机制有具体可修问题，下一 revision 提出新假设；
- INCONCLUSIVE：样本、成熟度、完整性或混杂不足；
- STOPPED_GUARDRAIL：安全、隐私、删除、质量或运行护栏触发。

任何一种结论都不允许写成“证明用户更依赖”“证明有心理改善”或其它超出指标的因果叙事。

## 10. 曝光与聚合边界

v1 不增加公共 `experiment_id` 事件属性，也不创建 exposure event 表。

对发布批次或产品日期 switchback：

1. 服务端从已注册的版本/日历解析当次低风险呈现；
2. 业务事实仍按原合同提交；
3. T0 受控查询临时把产品日期/版本映射到一个低基数变体；
4. 同一次计算内得到指标分子、分母和质量计数；
5. 立即释放任何 owner/cycle 粒度集合；
6. 只写满足 k=10、最多两个批准维度的 T4 聚合；
7. T4 沿用最长 13 个月、不可下钻、不可反查和删除历史说明。

个体随机 assignment 若未来提出，必须先完成：

- 更新 `PDM-ANALYTICS-001` 的目的、依据、标识、位置、访问、期限、删除、导出和受托方；
- 新增领域/数据库/API/Schema 和用户权利映射；
- 明确 sticky assignment、账户删除、关系删除、多端、同日重建与备份传播；
- S-29 架构、S-31 测试和安全隐私评审；
- 用户告知或同意的适用性核验。

完成前，个人随机实验生产 Gate 固定失败。

## 11. 质量、混杂与伪证检查

每次实验至少检查：

- 计划版本、日历、变体和代码版本匹配；
- 环境没有 PROD/STAGING 混合；
- 主指标 source contract 与 metric version 一致；
- 观察窗口内没有未记录的页面、Prompt、模型路由、价格、通知或渠道大改；
- template、Unknown、失败、删除和暂停按同一规则处理；
- 变体单元数量与预注册日历一致；
- 同日重复聚合没有倍增；
- 小样本与重叠切片不能差分个体；
- switchback 的星期、节假日、故障和渠道结构作为预注册限制披露；
- A/A 或合成 fixture 能发现错误映射时，先修数据，不解释业务差异。

## 12. 运行、回滚与沟通

开始前必须具备：

- CONTROL 稳定基线；
- 变体独立开关和 fail-closed 默认；
- 不迁移业务事实的回滚；
- Schema/安全/降级/删除/日期边界测试；
- 指标来源与聚合 fixture；
- owner、值守窗口和事件升级路径。

暂停或回滚时：

- 新请求返回 CONTROL；
- 已发布的当日内容保持原版本，不重抽；
- 不把暂停用户补发到另一变体；
- 记录稳定原因码，不保存用户列表或原文；
- 需要用户沟通时沿用事件响应规范，不能用营销文案淡化影响。

## 13. 固定验收 Fixtures

| Fixture | 输入 | 预期 |
|---|---|---|
| S26-FX-01 | 一个计划没有主指标 | 不能 REGISTERED |
| S26-FX-02 | 主指标在运行中从 M03 改为 M07 | 关闭旧 revision，新建计划；不能静默修改 |
| S26-FX-03 | 50～100 人 Beta 同时计划三个核心体验实验 | 拒绝；一次最多一个 |
| S26-FX-04 | 产品日期 switchback、某日服务故障 | 该日标异常/暂停，不改日历、不计作某变体失败 |
| S26-FX-05 | 个人随机 assignment 未更新 PDM | Production Gate 失败 |
| S26-FX-06 | 变体提高 M05，但 G02 删除 Gate 失败 | STOPPED_GUARDRAIL，不 ADOPT |
| S26-FX-07 | 每变体分母 9 | SUPPRESSED / INCONCLUSIVE，不显示精确比例 |
| S26-FX-08 | D1 cohort 尚未成熟 | pending，不进入最终效果判断 |
| S26-FX-09 | 模板降级在两个版本分布不同 | 按 S-25 计成功并披露 M21，不隐藏 |
| S26-FX-10 | 同 revision 聚合重跑 | 覆盖同 key，不重复累加 |
