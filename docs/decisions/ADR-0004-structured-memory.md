# ADR-0004：用途受限的结构化记忆，不使用向量数据库

- **状态**：Accepted
- **日期**：2026-07-22
- **接受日期**：2026-07-22
- **所属任务**：S-14 — 结构化记忆决策与规范
- **决策范围**：记忆来源、类型、授权、选择、有效期、模型上下文、删除传播与检索技术
- **决策所有者**：DailyEnergy 项目
- **相关文档**：[产品状态机](../product/state-machine.md)、[第一阶段 MVP](../product/mvp.md)、[数字朋友人格](../ai/personality.md)、[今日内容 Schema](../ai/daily-content-schema.md)、[七天总结 Schema](../ai/weekly-summary-schema.md)、[Prompt 规范](../ai/prompt-spec.md)、[记忆规范](../ai/memory.md)、[ADR-0003](./ADR-0003-ai-provider-abstraction.md)

## 1. 背景

DailyEnergy 的关系价值依赖“真的记得”，但记忆也是最容易破坏信任、隐私和事实边界的能力。

如果把用户自由文本、模型总结或历史结果全部放进一个通用记忆库，再用语义相似度检索，会产生以下问题：

- 模型可能把单次状态升级成长期人格、疾病、关系或财务结论；
- 用户无法清楚知道一条记忆从哪里来、为什么出现、还能用于什么；
- embedding 和向量索引会形成额外副本，增加删除、审计和跨环境隔离难度；
- 相似度、召回数量和模型摘要会让同一上下文选择不可解释、不可复现；
- 无关历史容易被发送给模型，扩大隐私披露和 Prompt 注入面；
- 删除源记录后，缓存、向量、摘要和已发布表达可能继续保留“幽灵引用”；
- 为了表现熟悉而频繁提及旧事，会让用户感到被监视或被产品强行制造亲密。

Accepted 产品基线已经决定：记忆只来自用户真实提供或系统真实记录的信息，必须可解释、可修改、可删除；不把所有自由文本自动转为长期记忆，不伪造共同经历。Accepted Schema 进一步要求每个记忆引用有源依赖和无源隐私回退。S-14 需要固定一种既能支持 MVP 关系连续性、又不会演变成开放聊天记忆系统的架构。

## 2. 决策

DailyEnergy 采用“**领域事实为源、用途授权为门、确定性投影为上下文**”的结构化记忆架构。

系统不建立可由模型任意写入的通用记忆文本池。称呼、表达偏好、重要事项、近期真实状态和关系事实继续由各自领域对象保存；记忆服务只负责验证来源与授权、按固定规则选择最小事实、生成一次调用可用的上下文快照，并记录服务端源依赖。

MVP 不创建 embedding，不使用向量数据库、语义相似度搜索、模型摘要检索或跨用户记忆检索。PostgreSQL 中按用户、类型、状态、用途、日期和修订建立的确定性查询足以支持当前规模与产品范围。

模型不能创建、修改、确认、合并或删除记忆。任何长期用户可见记忆都必须由用户明确保存或修改；系统派生事实必须能从权威源重新计算，不能伪装成用户说过的话。

现有 `daily-expression-zh-cn-v1` 与 `weekly-expression-zh-cn-v1` 保持无结构化记忆输入。启用任何新记忆槽必须创建新的 plan/input/Prompt/Schema 版本，通过 S-15 Safety 与 S-16 评测，并保留完整无记忆路径。

## 3. 决策细则

### 3.1 领域事实是唯一源

MVP 允许形成记忆候选的源只有：

1. `PROFILE_SETTING`：用户保存的安全称呼与表达偏好；
2. `IMPORTANT_MATTER`：用户主动创建的短事项、可选日期、状态和逐用途许可；
3. `RECENT_REAL_STATE`：晨间签到、晚间结构化反馈、任务与帮助度等权威记录的短期安全投影；
4. `RELATIONSHIP_FACT`：由有效点亮日和节点回执确定性派生的阶段或节点事实。

这些是来源类别，不授权复制全部源对象。晚间 note、支持文本、历史 AI 文本、渠道画像、页面行为、外部抓取数据和模型推断都不是记忆源。

名称、偏好、签到、事项和关系事实仍由对应领域服务拥有。不得为了“统一记忆”复制成另一份长期自然语言事实；需要索引时只保存不透明源引用、类型、用途授权和修订。

### 3.2 显式写入与用户控制

- 称呼和表达偏好只在用户保存设置后生效；恢复默认或删除后，旧修订不再使用。
- 重要事项必须由用户主动创建；事项文本不能由模型补写、扩展或自动归类为敏感结论。
- “允许在每日内容中提及”“允许周总结使用”“允许提醒”是不同用途，不互相推导；默认关闭，只有明确操作才授权。
- 当前设计未提供 `WEEKLY_SUMMARY` 独立许可，因此 MVP 周总结的记忆槽保持为空，不能借用 Daily 或提醒许可。
- 用户可以在现有资料、记录、重要事项和隐私入口查看、修改、暂停、完成或删除相应来源；不建立隐藏记忆管理页。
- 模型输出、内容帮助度和任务完成不能静默创建新的长期偏好。

### 3.3 用途绑定

每次使用必须匹配一个稳定用途：

- `ADDRESS_USER`：安全称呼；
- `EXPRESSION_STYLE`：同一人格的表达偏好；
- `DAILY_EXPRESSION`：未来版本的一次 Daily 受控表达；
- `WEEKLY_SUMMARY`：未来版本的一次 Weekly 受控表达；
- `IMPORTANT_MATTER_REMINDER`：用户主动设置的通用提醒；
- `RELATIONSHIP_MODULE`：第 1/3/4/7 日等确定性页面关系模块；
- `USER_MANAGEMENT`：向用户展示和管理自己的来源数据。

用途授权只允许更窄，不能由服务端、模型或运营后台自动扩大。数据分析、广告、渠道归因、模型训练、人工内容浏览和分享不是上述用途的别名，必须有独立合法依据和后续规范。

### 3.4 确定性选择

记忆解析器只接收用户、产品日期、workload、用途、允许源类型和版本化策略。候选按以下字段确定性筛选和排序：所有权、状态、用途许可、有效窗口、源修订、产品日期相关性、明确优先级和稳定 ID。

禁止使用 embedding 相似度、LLM 判断“最相关”、当前供应商输出、历史 AI 文本、随机数、页面停留或跨用户统计选择记忆。

一次 Daily 受控表达最多选择一个主动事项、一个近期状态槽和一个关系 token；称呼与风格属于 profile 投影，不占主动事项名额。一次 Weekly 受控表达最多选择一个明确获准的记忆事实。没有合格候选是正常结果，不能用较弱或未授权候选补位。

### 3.5 有效期与状态

- Profile setting 在当前修订有效、用途允许且未重置/删除时可用。
- Recent real state 只从当前日期之前最多两个产品日期选择，且只使用结构化值；不复制晚间 note。
- Dated important matter 只在确定性相关窗口内可进入候选；状态遵循 `ACTIVE / PAUSED / COMPLETED / EXPIRED / DELETED`。
- Undated matter 最多在创建后的七个产品日期具有主动提及资格；之后变为上下文 `EXPIRED`，但是否物理保存由 S-18 决定。
- Relationship fact 每次由仍有效的点亮与节点事实派生；单日或关系数据删除后必须重新计算。

这里的有效期只决定“还能否用于产品上下文”，不决定数据库、审计或备份物理保存期限。物理保留、依法例外、审计最小字段和备份清除由 S-18 / ADR-0005 决定，不能反向允许过期或已撤销事实继续进入活跃产品。

### 3.6 最小上下文投影

解析器为一次 invocation 创建不可变 `MemoryContextSnapshot`，分为：

- provider-facing 安全事实：类型、允许表达、必要显示值、时间关系和禁止推断；
- server-only 依赖：不透明 source ref、source revision、purpose/grant revision、segment paths、fallback paths 和有效期。

source ID、用户 ID、授权时间、删除原因、完整领域对象和内部审计不发送给模型。自由文本只有在用户明确保存为重要事项、授权当前用途、通过长度/字符/Safety 投影且新 Prompt 版本明确支持时，才可作为惰性 JSON data 发送；不得进入指令正文。

每个记忆事实必须绑定允许出现的精确段落和 allowed claim。模型不能自行决定引用哪条记忆、把一条记忆移动到别的字段或新增长期结论。

### 3.7 Prompt、Schema 与无记忆路径

- Daily/Weekly v1 的 memory slots 保持空，正常无记忆不是技术降级。
- 首个启用记忆的 workload 必须使用新版本 token，并在严格输出中携带 exact memory fact refs 或等价绑定。
- 记忆只能影响允许的文本槽，不能改变 RuleFacts、分数、band、focus、行动/任务/仪式 ID、Weekly 聚合或 fact selection。
- 同一候选必须同时包含所有受记忆影响字段及其已校验无源回退；禁止用第二次模型调用修复、从另一 attempt 借段落或删除后重新询问模型。
- memory resolver、授权服务或依赖校验不可用时，直接使用完整无记忆 plan/Prompt/template；不得把原始领域对象交给 Gateway 临时处理。
- 启用前必须通过 S-15 安全分类与 S-16 事实、人格、隐私、重复率、延迟和成本回归。

### 3.8 删除、撤销与并发

源删除、用途撤销、状态暂停/过期、资料换修订或关系数据删除发生后：

1. 新解析立即不再选择该源；
2. 相关上下文缓存、队列和未开始 invocation 失效；
3. 可取消的在途 provider 调用取消，迟到结果丢弃；
4. 发布前重新校验 source/grant revision，任一不匹配整份候选不得发布；
5. 已发布结果根据 SourceDependency 切换同一候选内预校验的无源回退，或在无法安全回退时整体失效；
6. 客户端与设备缓存失效，不显示已删除事项的标题或“曾经记得”提示；
7. 物理删除与受限审计按 S-18 执行，受限记录不能重新成为上下文来源。

删除传播不调用模型、不用最新 Prompt 重写历史，也不通过向量或日志恢复内容。

### 3.9 安全、隐私与审计

- 重要事项和真实状态按敏感个人内容处理，最小权限访问。
- S-15 接受前，用户自由文本事项不得进入普通 provider 上下文；命中高风险时按 S-15 固定流程处理，不能靠 Prompt 自我克制。
- 普通日志、指标、trace 和分析不记录事项文本、状态值、称呼、模型上下文或表达原文。
- 可记录稳定 purpose、source type、policy/version、结果代码、slot 数量、size bucket、匿名 trace ref 和不可逆 fingerprint。
- 用户看到的“为什么提到”使用可理解来源说明，不暴露内部 ID，例如“来自你主动记录并允许用于每日内容的事项”。
- 管理员不能编辑用户记忆来影响生成；受限支持访问、导出和审计由 S-18/S-21/S-22 定义。

## 4. 采用理由

该方案优先满足：

- 每条记忆都能回答“从哪里来、为什么用、何时失效、如何删除”；
- 当前小规模结构化数据可以用普通关系查询稳定选择；
- 不创建 embedding 副本，显著降低删除和隐私复杂度；
- 无记忆仍能完成完整核心旅程，记忆故障不会阻断用户；
- 模型只表达批准事实，不能成为事实数据库或记忆写入者；
- 未来若扩大记忆类型，必须逐类增加 Schema、用途和测试，而不是开放一个无限文本入口。

## 5. 备选方案

### 方案 A：把全部历史文本放入 Prompt

实现简单，但披露过量、容易注入、成本随历史增长，且无法证明每句话来源。拒绝。

### 方案 B：模型自动总结并写入长期记忆

看似自然，但模型会错误归因、把暂时状态固化，用户也难以理解何时写入。MVP 拒绝；未来如有明确场景，必须由用户逐条确认并创建新 ADR。

### 方案 C：embedding + 向量数据库语义检索

适合大规模非结构化知识检索，但当前只有少量、强类型、用户可控事实。它会增加副本、删除、召回解释、成本和运行依赖，不能提升当前核心假设验证。拒绝用于 MVP。

### 方案 D：通用 `key/value` 记忆表

字段少，但会把类型、用途、敏感性、有效期和删除语义推给调用方，最终形成隐藏自由文本池。拒绝；使用领域对象与显式投影。

### 方案 E：完全不做记忆

最安全且最简单，但无法验证“真实记忆是否提升关系感”的核心假设。保留完整无记忆路径，同时以受限结构化记忆做可关闭增量。

## 6. 影响

### 6.1 正向影响

- 记忆写入、读取、授权和删除职责清楚；
- 用户控制与产品实际使用一致，不存在隐藏模型记忆；
- 上下文选择可复现，可针对日期、用途和修订测试；
- 删除可以沿 source dependency 传播，不依赖语义搜索猜测；
- PostgreSQL 即可满足 MVP，不增加独立向量基础设施；
- Prompt 和 provider 披露保持小而可审计。

### 6.2 代价与限制

- 自然度低于“把全部历史交给模型”，需要精心设计安全事实投影；
- 每增加一种记忆都要增加领域契约、用途、有效期、回退和测试；
- 不使用相似度意味着系统不会自动发现远期模糊关联；这是当前有意边界；
- 已发布记忆表达必须携带依赖与回退，增加存储和验证复杂度；
- 精确物理保留和删除仍需 S-17/S-18 完成，S-14 只冻结活跃使用语义。

## 7. 实施与迁移要求

1. S-15 固化事项文本和记忆候选的 high-risk 前置分类；
2. S-16 把无记忆、合法记忆、越权、过期、删除竞态和 creepy repetition 纳入评测；
3. S-17 为 profile、matter、relationship、purpose grant、context snapshot 和 source dependency 建立领域关系；
4. S-18 固化物理保存、删除任务、审计、备份和完成时限；
5. S-19/S-20 实现修订、事务、缓存失效、用户管理和最小 API 投影；
6. S-29/AI-009 实现 deterministic resolver，不引入 vector store；
7. 任何启用记忆的 AI workload 必须先升级 Schema/Prompt 并通过 S-15/S-16 Gate。

## 8. 验收标准

- MVP 允许和禁止的记忆源可以枚举；
- 模型不能写入、合并或推断长期记忆；
- 每次使用都有精确 purpose、授权、有效窗口、源修订和段落依赖；
- 同一输入在同一策略版本下选择相同上下文；
- 没有合格记忆时完整无记忆路径仍可用；
- Daily/Weekly v1 不因本 ADR 自动获得记忆输入；
- 删除、暂停、过期或撤销后，新调用、在途结果、缓存和历史解析都不再泄漏源内容；
- 普通日志、分析和客户端不出现内部源、事项原文或隐藏记忆；
- MVP 不创建 embedding 或向量数据库；
- 配套 `memory.md` 给出可转换为实现和自动测试的精确规则。
