# DailyEnergy 内容布局与阅读节奏

- **文档状态**：Draft
- **所属任务**：S-03 — 交互状态与页面规格
- **最后更新**：2026-07-20
- **适用范围**：微信小程序移动端内容层级、字数预算、折叠和可读性
- **上游文档**：[人格手册](../ai/personality.md)、[页面规格](./screen-specs.md)
- **配套文档**：[交互状态](./interaction-states.md)

## 1. 文档目的

本文定义页面从上到下的信息顺序、首屏承载量、内容块尺寸、折叠规则和移动端阅读节奏，使“一分钟”不是渠道口号，而是可以在原型中检验的结构约束。

本文不指定最终颜色值、字号、字体、插画、Logo、数字朋友形象、设计 Token 或结构化 Schema。字数是中文移动端预算，用于限制密度；后续 Schema 应在不扩大阅读负担的前提下固化上限。

## 2. 内容布局原则

1. **先交付当下价值**：问候后立即出现今日重点，不先解释全部功能。
2. **一屏一个判断**：用户在任一视口只需要决定继续看、做一个动作或返回。
3. **事实分层**：真实状态、娱乐性今日能量和系统行为使用不同标题、容器和说明。
4. **一个主要行动**：建议正文只给一个主要行动；可选小任务必须处于次级层。
5. **渐进披露**：五维、娱乐元素、版本说明、隐私细节和帮助内容按需展开。
6. **短而完整**：删掉不影响理解的铺垫，不用大量图标替代清楚词语。
7. **缺失可见**：空白、缺失和离线都有文字说明，不靠灰色或断线让用户猜。
8. **情绪克制**：低状态页面减少刺激、动画和感叹，不把分数做成警报。
9. **不刻板化**：目标用户是 22～35 岁职场女性，但视觉与文案不默认粉色、撒娇称呼、恋爱或消费场景。
10. **内容可扫描**：标题、摘要、正文、操作的层级稳定，避免每天换结构制造新鲜感。

## 3. 移动端基线

- 以常见微信小程序竖屏、单手操作和系统字体缩放为基准；
- 页面采用单列主阅读流，不横向滚动核心内容；
- 主操作在安全区内可见，不能遮挡正文或系统手势；
- 点击目标满足移动端可操作尺寸，间距防止误触危险操作；
- 文本放大后允许页面变长，不截断核心说明；
- 键盘出现时输入字段和保存状态可见；
- 横屏、折叠屏和大屏可以增加留白，不增加新的信息层；
- 列表、卡片和图表的阅读顺序与 DOM/读屏顺序一致；
- 动画支持减少动态效果，装饰图不被读屏重复朗读。

本文不锁定具体像素，最终数值进入 design-system.md。

## 4. 内容类型标识

### 4.1 真实记录

包括：

- 晨间情绪、精力和睡眠；
- 晚间整体感受、帮助度、任务结果和可选一句话；
- 点亮、任务状态和缺失日期；
- 用户主动添加的重要事项。

布局要求：

- 使用“你的状态”“你的真实记录”等直接标签；
- 图表标题明确指标和样本天数；
- 不与今日能量共用同一种分数徽章；
- 删除后显示缺失，不用娱乐内容补齐。

### 4.2 娱乐与行动参考

包括：

- 整体能量与五维状态；
- 幸运色、幸运数字等低优先级元素；
- 规则结果的朋友式解释。

布局要求：

- 首次出现时标注“娱乐与行动参考”；
- 不使用医疗、财务或灾害警报式红绿信号；
- 分数若保留，必须同时有中性文字含义；
- 不能把娱乐曲线放进真实趋势图；
- 幸运元素位于主要行动之后。

### 4.3 朋友式表达

包括问候、核心提示、解释、行动和关系节点。

布局要求：

- 同一段只承担一个作用；
- 不使用聊天气泡和输入框，避免形成无限聊天预期；
- 可有数字朋友的视觉占位，但不暗示真人身体或在线状态；
- 记忆引用与普通正文同层，不使用“我知道你所有事”的强调样式；
- 安全页面不沿用轻松人格装饰。

### 4.4 系统与权限

加载、离线、失败、降级、删除和权限说明使用稳定系统层：

- 语气清楚、非技术；
- 不伪装成数字朋友情绪；
- 不用运势词解释故障；
- 操作影响和恢复路径比品牌表达优先。

## 5. 全局字数预算

人格手册给出的预算继续生效，S-03 补充页面结构上限：

| 内容单元 | 推荐预算 | 布局要求 |
|---|---:|---|
| 页面标题 | 4～12 字 | 一行优先 |
| 页面副说明 | 20～60 字 | 最多 2～3 行 |
| 问候 | 8～24 字 | 不与解释合并 |
| 核心提示 | 20～50 字 | 首屏最多一条 |
| 今日解释 | 60～140 字 | 1～2 段，可完整阅读 |
| 主要行动 | 15～45 字 | 动词开头，一件事 |
| 可选任务 | 10～35 字 | 不超过主要行动 |
| 五维单项说明 | 12～35 字 | 默认仅重点项完整 |
| 娱乐元素说明 | 8～24 字 | 不占首屏 |
| 降级/离线说明 | 15～45 字 | 原位一条 |
| 晚间收尾 | 15～50 字 | 不追加新任务 |
| 七天摘要标题 | 8～20 字 | 不下诊断 |
| 七天总结正文 | 120～260 字 | 2～4 段，显示数据来源 |
| 空状态说明 | 20～70 字 | 说明现状与下一步 |
| 确认弹层影响 | 30～100 字 | 明确对象、不可逆和后果 |
| 承接首屏总正文 | 60～120 字 | 不含按钮和法定链接 |
| FAQ 单条答案 | 40～180 字 | 过长则分层说明 |

规则：

- 预算是上限约束，不要求填满；
- 用户自定义称呼、事项和反馈使用独立输入上限，后续 Schema 决定；
- 截断不能改变风险、删除或权限含义；
- 安全固定文案由专业安全规范确定，不受日常人格的短文案优化覆盖。

## 6. 一分钟阅读预算

原型目标分配如下，不是强制倒计时：

| 阶段 | 目标阅读/操作 |
|---|---:|
| 承接理解 | 5～10 秒 |
| 第一次认识 | 10～15 秒 |
| 三项签到 | 8～12 秒 |
| 生成等待 | P95 工程目标内；可离开 |
| 今日重点与行动 | 20～30 秒 |
| 点亮 | 1～3 秒 |
| 合计 | 约 45～70 秒 |

返回用户跳过承接和认识，核心流程应更短。页面不显示倒计时，也不因超过一分钟责备用户。

## 7. 承接页 ENT-001

### 7.1 首屏顺序

1. 产品名或最小品牌标识；
2. 一句话“每天一分钟的数字朋友”；
3. 一句即时收益；
4. “约一分钟”；
5. 主操作“开始今天的一分钟”；
6. 真实界面或三步流程的轻量视觉；
7. 娱乐与专业边界短说明；
8. 隐私入口。

主操作应在常见首屏内。隐私和边界可在首屏末端可见，但完整说明下沉。

### 7.2 渠道差异

小红书和抖音可以替换首屏示例和句子顺序，但必须保持：

- 相同产品定位；
- 相同一分钟承诺；
- 相同输入—回应—行动结构；
- 相同娱乐、专业和隐私边界；
- 不增加渠道专属虚假能力。

## 8. 第一次认识 ONB-001

从上到下：

1. “怎样称呼你”；
2. 可选输入与“留空也可以”；
3. “我怎样说话更合适”；
4. 三张表达示例卡；
5. 同一人格说明；
6. 主操作。

三张卡使用同一事实场景，例如“睡眠不太够、今天有一个重要任务”，每张 25～60 字。卡片差异来自温柔度、幽默度和直接度，不能改变建议、事实或安全边界。

展示规则：

- 移动端纵向卡片优先，避免横滑造成遗漏；
- 卡片标题和示例同时可点击；
- 选中不只靠颜色，使用勾选和文字；
- 未选择时主操作仍可用，并说明使用默认平衡方式；
- 称呼输入与风格区不收集额外个人资料。

## 9. 今日签到 DLY-001

布局采用三段连续选择，不拆成三页：

1. 日期和时段；
2. “这是你的真实状态”；
3. 情绪组选项；
4. 精力组选项；
5. 睡眠组选项；
6. “说不准也可以”；
7. 主操作“生成今天”。

每组要求：

- 标签在选项上方；
- 选项不只用表情或颜色；
- 业务等级从低到高，但不出现“糟糕/优秀”评价；
- “说不准”在同组末端，视觉次级但可发现；
- 选择后不自动跳页；
- 三组在常见屏幕上允许自然滚动，主操作不遮挡最后一组；
- 提交错误在对应组附近，不用顶部统一红条替代。

## 10. 生成 DLY-002

页面保持低密度：

1. 轻量动效或静态状态；
2. 一句当前事实；
3. 一句稳定性说明；
4. 超过阈值后的“稍后来看”。

同一时刻只显示一条事实短句，最多轮换 2～3 条；不展示虚构的“分析情绪 30% / 读取宇宙 70%”。动效不承载实际进度，关闭动画后信息仍完整。

等待页不放：

- 五维占位分数；
- 随机每日文案；
- 重新抽取；
- 分享、通知和商业入口；
- 阻止退出的倒计时。

## 11. 今日内容 DLY-003

### 11.1 首屏上限

常见首屏只承载：

1. 日期、记录和设置入口；
2. 8～24 字短问候；
3. “娱乐与行动参考”标签；
4. 整体能量；
5. 默认重点维度；
6. 20～50 字核心提示；
7. 指向下一段的唯一主操作或明确滚动提示。

首屏不同时展示：

- 全部五维详解；
- 幸运色和幸运数字；
- 长关系文案；
- 分享卡；
- 通知授权；
- 晚间表单；
- 多个等权按钮。

### 11.2 长页顺序

1. **今日抬头**：日期、问候、整体能量；
2. **今日重点**：一项重点维度和核心提示；
3. **为什么**：朋友式解释；
4. **今天怎么做**：一个主要行动；
5. **如果愿意**：可选小任务；
6. **留下今天**：点亮；
7. **再看看**：五维展开和低优先级娱乐元素；
8. **这条有用吗**：帮助度；
9. **关系与真实回看**：晚间、第 3/4/7 天卡片；
10. **分享**：末端、先预览；
11. **产品边界短链接**：低干扰页尾。

当页面在回访/完成状态打开时，已点亮状态可简化但不改变内容顺序。

### 11.3 主操作随阅读阶段变化

- 首屏：“看看今天怎么做”，滚动到行动；
- 行动完整呈现后：“点亮今天”；
- 点亮后：显示“今天已留下”，不再突出第二个按钮；
- 晚间时段：晚间卡片可成为内容末端主入口，但不覆盖已完成状态。

底部固定操作如采用，必须避免遮挡内容和微信安全区；同一时间只出现一个强调按钮。

## 12. 五维渐进展开 CMP-007

- 默认完整展示与主要行动最相关的 1 项；
- 其余 4 项显示名称、中性等级/短标签；
- “展开全部”一次打开，打开后“收起”回到摘要；
- 不创建五个详情页；
- 单维说明 12～35 字；
- 多个低分时不形成连续警报墙，排序由相关性而非单纯从低到高；
- 整体和五维都注明娱乐参考；
- 读屏顺序为名称、等级、说明、展开状态；
- 图形必须有文字等价物。

五维最终命名和权重不在 S-03 决定，布局使用上游暂定词汇时应保持可替换。

## 13. 行动、任务与点亮

### 13.1 主要行动

行动卡只包含：

- 一句行动；
- 必要时一句为什么；
- 不超过一个时间/范围约束。

不包含多步清单、连续挑战、课程链接或“必须完成”。

### 13.2 可选小任务 CMP-005

位于主要行动之后，视觉权重更低：

- 初态：“我想试试”；
- 选择后显示“想试试”；
- 后续可标记“已完成”或“今天先不做”；
- “稍后”仅关闭选择；
- 状态改变后给轻量确认，不触发庆典、积分或羞辱。

### 13.3 点亮 CMP-004

点亮区包含：

- 主操作；
- “不需要完成任务也可以点亮”的低干扰说明；
- 成功后的日期和克制视觉反馈。

点亮反馈不自动弹分享或通知。动效最多一次且可减少；重复进入显示稳定完成状态。

## 14. 帮助度、关系卡与晚间入口

- CMP-010 放在行动和点亮之后，单行三选，不先弹问卷；
- CMP-001、CMP-002、CMP-003 同一天最多出现一张主关系卡，避免抢占核心；
- 关系卡只在核心价值之后出现；
- CMP-006 在 18:00 后提升可见度，早于该时段只在“更多/现在回看”次级入口；
- 卡片关闭后当天不反复弹；
- 低状态或安全状态下隐藏非必要邀请；
- 第 7 天卡片即使记录不完整也使用“已经留下的记录”，不说“完美连续”。

## 15. 晚间反馈 EVE-001

单页顺序：

1. 日期与“你的真实记录”；
2. 今天整体感觉；
3. 建议帮助度；
4. 任务结果；
5. 可选一句话；
6. 主操作“保存今天”；
7. 简短收尾。

布局要求：

- 三组选择保持与晨间控件一致的可访问性；
- 一句话输入最后出现，明确“可不填”；
- 不把键盘打开作为必经步骤；
- 已保存后顶部显示更新时间和“可以修改”；
- 收尾在原页出现，不创建成功页；
- 不插入新行动、分享或聊天输入。

## 16. 记录与七天趋势 REC-001

### 16.1 页面顺序

1. 标题、日期范围、返回今天；
2. “你的真实记录”；
3. 样本数和缺失天数；
4. 七天点亮；
5. 情绪、精力、睡眠趋势；
6. 缺失说明；
7. 帮助度和任务概览；
8. 七天总结或资格说明；
9. 最近日记录；
10. 分享七天概览的次级入口。

### 16.2 图表要求

- 一张图只回答一个问题；
- 真实指标和娱乐能量不共轴、不叠线；
- 缺失点留空，不用前值、均值或 AI 推断补齐；
- 颜色之外使用形状、标签或文字；
- 同时提供一段简短文字摘要；
- 明确“基于 N 天记录”；
- 1～2 天显示点而不下趋势结论；
- 小屏下优先纵向排列，不压缩到难以点击或阅读。

### 16.3 七天总结

- 只有 7 天窗口且数据条件满足时展示完整总结；
- 正文 120～260 字；
- 摘要旁提供“依据哪些记录”；
- 缺失部分逐项说明；
- 不诊断、不评判自律、不验证运势准确度；
- 总结失败时保留真实图表和固定说明。

## 17. 历史日详情 REC-002

顺序：

1. 日期与返回；
2. 真实晨间状态；
3. 分隔说明；
4. 当时的娱乐性今日能量；
5. 当时解释和行动；
6. 点亮与任务；
7. 晚间真实反馈或缺失；
8. 版本说明入口；
9. 删除当日记录。

“真实”与“娱乐”之间至少使用标题、容器和说明三种中的两种差异，不能只换颜色。删除置于页尾危险区，不与返回等权。

## 18. 重要事项 MEM-001 / MEM-002

### 18.1 列表

1. “你主动让我记住的事”；
2. 用途和控制说明；
3. 有效/近期事项；
4. 即将到期；
5. 已完成/停用折叠；
6. 新增。

事项卡只显示完成识别所需的短标题、日期和许可摘要，不在列表暴露长敏感文本。

### 18.2 编辑

1. 用途说明；
2. 事项短文本；
3. 可选日期；
4. 每日内容提及许可；
5. 提醒许可；
6. 状态；
7. 保存；
8. 编辑态危险区删除。

开关旁使用自然语言解释结果，不用只有“允许/禁止”的模糊标签。提醒被拒绝时，仅对应区域显示不可用。

## 19. 分享预览 SHR-001

顺序：

1. 明确标题“将公开这些内容”；
2. 与最终输出一致的卡片预览；
3. 有限模板：今日一句话、行动建议、七天点亮概览；
4. 公开字段清单；
5. 主操作“分享”；
6. 取消。

默认隐藏字段必须在预览真实消失，而不是仅靠说明承诺。预览内容过长时重新选择受控摘要，不能随意截断到改变意义。分享失败留在预览，不改变今日流程。

## 20. 设置、隐私与删除

### 20.1 设置目录 SET-001

使用标准单列目录：

- 资料与表达偏好；
- 重要事项；
- 提醒；
- 隐私与数据；
- 帮助、反馈与关于。

每行使用简短状态摘要，例如“默认表达”“2 件有效事项”，不得把敏感事项标题展示在目录。

### 20.2 资料 SET-002

复用 ONB-001 的称呼和同场景三卡，但增加：

- 当前选择；
- 生效范围；
- 恢复默认；
- 保存成功状态。

### 20.3 隐私与数据 SET-004

分组顺序：

1. 收集与用途；
2. 查看和管理；
3. 导出；
4. 删除单日；
5. 删除关系数据；
6. 注销；
7. 完整隐私说明。

危险操作位于独立分组，按钮清楚但不使用高刺激大面积警报色。

### 20.4 注销 SET-006

专页顺序：

1. 明确动作；
2. 删除范围；
3. 处理时间和保留例外；
4. 不可逆说明；
5. 身份验证；
6. 最终确认；
7. 取消。

不能通过折叠隐藏关键影响；不显示连续天数损失、数字朋友挽留或优惠。

## 21. 帮助与边界 SET-005

首屏优先回答：

- DailyEnergy 是什么；
- 今日能量用于什么；
- 它不是什么专业服务；
- 数据和记忆怎样控制。

FAQ 使用折叠列表；默认不展开全部。反馈表先选分类，再选择是否提供说明；附带上下文必须单独确认并展示字段类别。

## 22. 系统、错误和安全布局

### 22.1 系统页

SYS-003 使用居中或上部稳定结构：

1. 状态标题；
2. 影响说明；
3. 已保存内容说明；
4. 主操作；
5. 支持/退出；
6. 参考号。

不使用大面积错误插画掩盖恢复信息。

### 22.2 内联错误

- 字段错误贴近字段；
- 模块错误占原模块位置；
- 页面错误才使用整页；
- 错误消息后紧邻可执行动作；
- 修复后错误自动移除并由读屏通知。

### 22.3 SAFE-001

安全页使用全屏、低干扰、无娱乐装饰布局：

1. 直接确认；
2. 立即安全行动；
3. 紧急服务；
4. 可信任现实人员；
5. 审核资源；
6. 受控后续。

主操作必须在无需长滚动的位置。地区资源加载失败时，通用紧急说明仍在首屏。页面不出现普通顶部导航、分数、幸运元素、点亮、分享、任务、幽默或数字朋友依赖话术。

## 23. 管理后台布局边界

- 侧边一级导航不超过已登记的 ADM-001～008；
- 页面顶部固定环境、时间范围、版本和权限上下文；
- KPI 卡必须同时显示定义入口、样本量和更新时间；
- 表格默认脱敏，敏感列不通过横向滚动偷偷暴露；
- 空状态保留筛选条件；
- 详情抽屉/页与列表上下文一致；
- 发布、回滚、删除和安全处理的主操作与普通筛选明显分开；
- 图表不把无数据绘制为 0；
- 小样本优先显示人数，不只显示百分比；
- 管理后台不提供修改用户签到、反馈或当天分数的控件。

## 24. 折叠、截断与长内容

可以折叠：

- 非重点五维；
- 已完成/停用事项；
- FAQ；
- 版本说明；
- 完整隐私条款；
- 后台低优先级详情。

不能折叠到默认不可见：

- 当前主要行动；
- 点亮条件说明；
- 分享实际公开字段；
- 删除范围与不可逆性；
- 安全立即行动；
- 权限用途；
- 趋势样本量和缺失说明。

截断规则：

- 用户事项列表可单行截断，但详情可完整查看；
- 朋友式正文不在中句截断；
- 确认和安全文案不得截断；
- 卡片预览必须与最终分享一致；
- 超出 Schema 上限的生成内容不能用 CSS 隐藏来假装合格，应在生成/校验层处理。

## 25. 可访问性检查

每个原型页面至少验证：

- 系统字体放大到常见较大档位仍能完成操作；
- 颜色关闭或色觉差异下仍能识别状态；
- 读屏能读出选项名称、选中、展开、加载和错误；
- 点击目标足够大且危险操作不相邻；
- 动画关闭后信息不丢失；
- 图表有文字摘要和缺失说明；
- 焦点在弹层打开、关闭和错误后回到合理位置；
- 键盘不遮挡保存按钮和错误；
- 长称呼、空称呼与中英文混排不破坏布局；
- 低状态和安全内容不使用闪烁、强震动或刺激庆典。

## 26. 原型内容样本要求

S-04 原型至少准备：

- 三种表达偏好的同事实样本；
- 高、中、低状态各一组今日内容；
- 多个低分但不恐惧的样本；
- 有真实记忆、无记忆和个性化降级样本；
- 首次、第 3 天、第 4 天、第 7 天和中断回来；
- 任务完成、今天先不做和未标记；
- 1、3、7 天真实趋势及缺失日；
- 历史日删除前后；
- 离线、局部错误、完整失败和模板降级；
- 高风险固定页面占位，文案标记“待专业安全评审”，不可临时生成。

## 27. 布局完成定义

- 首次核心流程在目标时长内没有不必要页面；
- DLY-003 首屏符合上限，长页顺序交付行动后再扩展；
- 五维默认一项，其余可访问展开；
- 真实记录、娱乐参考和系统行为至少用标题与容器清楚区分；
- 所有关键文案符合人格手册预算；
- 删除、分享和安全关键信息默认可见；
- 缺失、离线和降级不依赖颜色解释；
- 页面支持文本放大、读屏、减少动态效果和单手操作；
- 没有隐式聊天、角色、商城、社区、专业排盘或月度功能。
